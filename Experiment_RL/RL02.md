# RL02: Qwen3-VL Long-CoT Option-Logit Gain Reward Plan

本文档是 `RL.md` 之后的第二版 RL 实验计划，重点修订 Experiment C。

当前结论是：

```text
Experiment A / A0 已经建立了 answer-only GRPO baseline。
text-only Qwen2.5-1.5B 的 Experiment C pilot 证明了 option-logit reward 可以接入 VERL，
但它不是方法有效性的主要证据。
```

原因是 text-only 1.5B pilot 没有满足 Experiment C 真正需要的条件：

```text
1. 模型不是自然长 CoT / thinking 模型。
2. response 普遍较短，option-logit margin gain 的中间过程信号被压弱。
3. raw option bonus 平均量级很小，基本被 answer reward 方差淹没。
```

因此，下一版正式验证应回到：

```text
Qwen3-VL-8B-Thinking
MathVerse multimodal MCQ
max_response_length = 16384
group-zscored option-logit margin gain reward
```

---

## 1. Compared With RL.md

相比 `RL.md` 和最早的 Experiment C 方案，本版主要修改如下。

### 1.1 Experiment C 改名为 C2-long-zscore

旧版 Experiment C 的核心是：

```text
R_total = R_answer + lambda * R_gain
```

但 text-only pilot 说明 raw gain 的量级可能非常小。例如：

```text
option_logit_gain mean ~= -0.00716
option_bonus mean     ~= -0.00143
```

这个量级很难改变 GRPO 的组内 advantage 排序。

新版 C2 使用 group-level zscore：

```text
B_gain = clip(zscore_group(R_gain_raw), -2, 2)
R_total = R_answer + lambda * B_gain
```

这里的 `zscore_group` 是同一道题的 rollout group 内归一化，而不是全 batch 归一化。

### 1.2 0.0 probe 只做诊断，不参与 reward

旧版可能把 0.0 / prompt-only 位置作为 gain 的起点。

但之前实验里 prompt-only margin 基本无信号：

```text
prompt_only_margin AUROC ~= 0.50
```

text-only pilot 也观察到：

```text
option_margin_start 基本固定
```

因此新版保留 0.0 probe 作为诊断 baseline，但不参与 reward gain 计算。

### 1.3 必须先做 Qwen3-VL 资源探测

之前 Qwen3-VL + VERL 路线出现过 CPU/Ray OOM：

```text
ray.exceptions.OutOfMemoryError
WorkerDict.actor_rollout_ref_init_model memory ~= 104GB
node memory total ~= 125GB
```

所以不能直接跑 500 questions / 125 steps / rollout.n=8。

新版先做 resource smoke，逐步测试：

```text
max_response_length: 1024 -> 4096 -> 8192 -> 16384
rollout.n: 2 first
```

### 1.4 关注 CoT collapse

Qwen3-VL-8B-Thinking 在 RL 初期可能学到短答 shortcut，导致 thinking 长度骤降。

新版把 response length / think length 作为硬监控项。如果训练早期出现长度坍缩，则暂停解释 C2 效果。

## 5. Reward Definition

### 5.1 Option Logit Margin

对每条 rollout，在若干 response prefix 上读取 A/B/C/D logits。

如果正确答案是 `C`：

```text
margin_j = logit_C_j - max(logit_A_j, logit_B_j, logit_D_j)
```

不使用 raw `top_option`，因为之前已经观察到 A/B/C/D label logits 有强 option prior，尤其偏向 A。

### 5.2 Probe Points

记录用 probe：

```text
0.0, 0.25, 0.50, 0.75, 0.90
```

reward 用 probe：

```text
0.25, 0.50, 0.75, 0.90
```

`0.0` 只记录，不参与 reward。它用于诊断 prompt-only margin 是否仍然无信号。

### 5.3 Raw Gain

```text
gain_25_50 = margin_0.50 - margin_0.25
gain_50_75 = margin_0.75 - margin_0.50
gain_75_90 = margin_0.90 - margin_0.75

R_gain_raw =
mean([
  clip(gain_25_50, -c, c),
  clip(gain_50_75, -c, c),
  clip(gain_75_90, -c, c)
])
```

第一版建议：

```text
c = 0.5
```

### 5.4 Group Zscore Bonus

对同一道题的 rollout group 做 zscore：

```text
B_gain = clip(zscore_group(R_gain_raw), -2, 2)
```

如果某个 group 的 std 太小：

```text
std_group < eps
```

则该组的 `B_gain` 设为 0，避免把数值噪声强行放大。

### 5.5 Total Reward

```text
R_total = R_answer + lambda * B_gain
```

第一版建议：

```text
lambda = 0.2
```

如果出现不稳定、length collapse、format hacking 或明显 reward hacking，再降到：

```text
lambda = 0.1 或 0.05
```

## 6. Probe Cost Strategy

直接做多次 prefix forward 的成本很高：

```text
5 probes * rollout.n * long prefix forward
```

在 `rollout.n=8`、`max_response_length=16384` 时，probe forward 可能比 rollout generation 还贵。

优先实现思路：

```text
对同一条完整 response 做一次 causal full-sequence forward，
然后在多个 probe token 位置读取 logits。
```

decoder-only causal LM 在位置 `t` 的 logits 只依赖 `t` 及之前 token，因此一次完整 forward 理论上可以同时获得多个 prefix 位置的 logits。

如果 full-sequence multi-position probe 在 Qwen3-VL / VERL reward 环境里实现困难，先降级为更少 probe：

```text
logged probes: 0.0, 0.25, 0.50, 0.90
reward probes: 0.25, 0.50, 0.90
```

smoke 阶段必须记录：

```text
timing_s/gen
timing_s/adv
option_probe_count
option_probe_failed
```

如果：

```text
timing_s/adv < 1.5 * timing_s/gen
```

则当前 probe 实现的成本可以接受，允许进入 pilot。

如果：

```text
timing_s/adv > 2 * timing_s/gen
```

则正式版不能直接使用当前 probe 方案，先降级到 3 个 probe：

```text
logged probes: 0.0, 0.25, 0.50, 0.90
reward probes: 0.25, 0.50, 0.90
```

如果降级后仍然：

```text
timing_s/adv > 2 * timing_s/gen
```

则停止进入 pilot，先优化 probe 实现，例如 full-sequence multi-position logits 或 KV/cache 复用。

如果处于中间区间：

```text
1.5 * timing_s/gen <= timing_s/adv <= 2 * timing_s/gen
```

可以只跑更小 pilot，并把 probe cost 作为主要风险记录。

## 8. Execution Stages

### Stage 0: Resource Smoke

目的：

```text
确认 Qwen3-VL-8B-Thinking + VERL + GRPO 能在 H200 上跑起来，
并找到最大可承受 max_response_length。
```

设置：

```text
reward = answer-only
rollout.n = 2
train_batch_size = 1
total_steps = 2
val_before_train = false
save_freq = -1
test_freq = -1
```

逐级测试：

```text
max_response_length = 1024
max_response_length = 4096
max_response_length = 8192
max_response_length = 16384
```

通过条件：

```text
1. 不出现 CPU/Ray OOM。
2. GPU 显存稳定。
3. 能完成至少 2 个 update。
4. response_length/mean 有明确长 CoT 信号。
```

第 4 条具体定义为：

```text
理想通过: response_length/mean > 0.3 * max_response_length
例如 max_response_length=16384 时，mean > 5000。

最低通过: response_length/mean >= 500
低于 500 说明模型没有进入 thinking 模式，即使没有 OOM，也不能进入 C2 reward smoke。
```

### Stage 1: CoT Generation Verification

目的：

```text
确认模型真的处于 thinking / long-CoT 模式。
```

做法：

```text
用 Stage 0 找到的最大可用 max_response_length。
采样 10-20 个 validation 样本。
人工或脚本检查 response。
```

检查：

```text
1. 是否存在长 thinking 段。
2. 是否出现 <think>...</think> 或等价 thinking 格式。
3. mean response tokens 是否明显大于短答。
4. 是否大量过早输出 final answer。
5. generation config / chat template 是否启用 thinking mode。
6. 图文 prompt 是否按 Qwen3-VL multimodal 格式正确传入。
```

如果：

```text
mean response tokens < 500
```

则先检查 prompt template / chat template / thinking mode，不进入 C2 reward smoke。

### Stage 2: C2 Reward Smoke

目的：

```text
验证 option-logit zscore gain reward 的工程路径和数值尺度。
```

设置：

```text
model = Qwen3-VL-8B-Thinking
reward = answer + zscored option-logit gain
rollout.n = 2
steps = 3
max_response_length = Stage 0 最大可用长度
```

检查：

```text
option_probe_failed ~= 0
option_probe_count 正常
R_gain_raw 有非零方差
B_gain 经过 zscore 后量级可与 answer reward 竞争
within-group std(B_gain) > 0 的 group 比例足够高
all-correct / all-wrong group 中 B_gain 提供非零排序
fraction of groups where B_gain changes rollout ranking 非零
timing_s/adv 不超过 timing_s/gen 的 2 倍
response_length 没有立刻塌缩
```

Stage 2 通过标准：

```text
1. option_probe_failed 接近 0。
2. within-group std(B_gain) > 0 的 group 占比不能接近 0。
3. all-correct / all-wrong group 里，B_gain 能提供非零 ranking 的比例不能接近 0。
4. B_gain 的 std 经过 group zscore 后接近可用尺度，而不是全 0。
5. timing_s/adv < 1.5 * timing_s/gen 可直接通过；
   1.5x-2x 只允许小 pilot；
   >2x 必须先降级 probe 或优化实现。
6. response_length 没有在 3 steps 内明显塌缩。
```

## 9. Metrics And Decision Criteria

### 9.1 Main Metrics

```text
validation accuracy
clean accuracy
answer_reward
total reward
response_length/mean
response_length/clip_ratio
format validity
option distribution A/B/C/D
```

### 9.2 C2 Diagnostics

```text
R_gain_raw mean/std
B_gain mean/std
option_bonus mean/std
option_probe_failed
option_probe_count
option_margin_0.0
option_margin_0.25
option_margin_0.50
option_margin_0.75
option_margin_0.90
```

### 9.3 GRPO-Relevant Diagnostics

重点不是只看 batch mean，而是看同 prompt 的 group 内是否改变排序：

```text
within-group corr(R_answer, B_gain)
within-group std(B_gain)
fraction of groups where within-group std(B_gain) > 0
fraction of groups where B_gain changes rollout ranking
fraction of all-correct / all-wrong groups where B_gain provides nonzero ranking
```

### 9.4 Success Criteria For C2

C2 初步有意义需要至少满足：

```text
1. probe_failed 接近 0。
2. B_gain 在 group 内有非零方差，且 within-group std(B_gain)>0 的 group 占比不能接近 0。
3. all-correct / all-wrong group 中 B_gain 能提供非零排序作用。
4. option bonus 不是全被 answer reward 淹没。
5. response_length 没有塌缩。
6. C2 在同 seed pilot 中不低于 A1-long，并至少在 process diagnostics 上有正向变化。
```

如果 accuracy 没提升，但 C2 明显提高正确答案 margin gain，可以视为 process signal 有效但未转化为最终正确率，需要再调 reward 权重或训练规模。

## 10. Stop Conditions

以下情况应暂停，不继续正式 500 题：

```text
1. Qwen3-VL answer-only resource smoke 仍然 CPU/Ray OOM。
2. 16384 不可承受，且 8192 以下也不能稳定跑。
3. 模型没有生成长 thinking，mean response tokens < 500。
4. C2 reward smoke 中 option_probe_failed 明显非零。
5. within-group std(B_gain)>0 的 group 占比接近 0。
6. all-correct / all-wrong group 中 B_gain 基本不能提供非零排序。
7. timing_s/adv > 2 * timing_s/gen，且无法通过减少 probe 缓解。
8. 训练早期出现明显 CoT collapse。
9. C2 导致 option distribution 或 final answer format 明显异常。
```

## 11. CoT Collapse Monitoring

RL 可能让 thinking 模型学到短答 shortcut。

必须监控：

```text
response_length/mean
response_length/p50/p90
think_length/mean if available
response_length/clip_ratio
early final-answer phrase rate
```

如果 step10/25 后出现：

```text
mean response tokens 从几千降到几百或几十
```

或更严格地：

```text
连续 2 个 validation checkpoint 内 response_length/mean 下降超过 50%
```

则当前实验不能解释为 option-logit gain 无效。应先处理 length collapse，例如：

```text
1. format reward / thinking-format constraint
2. mild length floor reward
3. final-answer-before-thinking penalty
4. 降低 lambda 或 learning rate
```

这些改动应作为后续 C2.1，而不是混入 C2-long-zscore 第一版。
