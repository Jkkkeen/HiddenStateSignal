# RL03: Format-Agnostic Answer-Likelihood Trajectory Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use `superpowers:subagent-driven-development` (recommended) or `superpowers:executing-plans` to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace A/B/C/D-specific option-logit rewards with a controlled, format-agnostic answer-likelihood trajectory, validate that its gain is a real process signal, and only then test it as GRPO reward on symbolically verifiable free-form math.

**Architecture:** The work has three gated stages. Stage A performs an `interface x answer representation` audit on existing MathVerse rollouts. Stage B verifies the selected signal on frozen-policy GSM8K/MATH rollouts. Stage C runs matched answer-only versus answer-likelihood-progress GRPO experiments only if the earlier process-signal gates pass. Stages A/B are entry tickets; Stage C is the decisive test of the paper claim.

**Tech Stack:** Qwen3/Qwen3-VL, Hugging Face Transformers, vLLM, VERL, GRPO, PyTorch, SymPy, `math-verify`, pandas/NumPy, question-clustered bootstrap.

## 1. What Changes Relative To RL02

### 1.1 The primary target is answer content, not A/B/C/D

Old C2 target:

```text
correct option letter token among A/B/C/D
```

RL03 target:

```text
canonical correct answer content, for example:
  "100 degrees"
  "1/2"
  "sqrt(5)"
```

MCQ option labels are removed from the content target. The same scoring definition must later work for free-form questions with no options.

### 1.2 The answer interface is a controlled variable

The original option-logit work used:

```text
Given the reasoning so far, the answer is (
```

The format-agnostic proposal uses a neutral cue such as:

```text
Final answer:
```

Changing both cue and target representation at once would confound the audit. RL03 therefore treats the answer interface and target representation as separate experimental factors.

### 1.3 Level and process claims have different gates

The following result is not enough for process supervision:

```text
late/final gold-answer likelihood predicts final correctness
```

That is a confidence/verifier result. The RL process claim requires:

```text
gold-answer likelihood gain or trajectory slope
predicts correctness within the same question
```

If level passes but gain/slope fails, the process-reward branch stops.

### 1.4 MCQ becomes a backward-compatibility sanity check

MathVerse is no longer the main RL battlefield. It is used to answer:

```text
Does answer-content scoring preserve the known MCQ signal
without depending on option labels or a specific cue?
```

The main positive RL experiment, if justified, moves to symbolically verifiable free-form math.

### 1.5 Free-form does not initially require generated negatives

The primary method uses only the accepted reference answer. Hard-negative contrastive scoring is an ablation and possible enhancement, not a prerequisite.

## 2. Scientific Hypotheses

### H1: Interface robustness

The correctness-discriminative signal should not exist only under the original parenthesized MCQ cue.

```text
Expected evidence:
  letter/content gain remains directionally consistent across neutral answer cues
```

### H2: Representation robustness

At the same neutral answer interface, scoring answer content should retain useful within-question discrimination compared with scoring option letters.

```text
Expected evidence:
  content gain AUC is not explained by A/B/C/D token priors
```

### H3: Process validity

Correct reasoning should increase gold-answer likelihood more than incorrect reasoning does.

```text
Primary evidence:
  within-question AUC of gold gain/slope
  paired incremental discrimination beyond the matched late/final level

Not sufficient:
  high final or trimmed gold level alone
  high gain AUC when gain and final level induce the same rollout ranking
```

Mechanism hypothesis:

```text
At the early anchor, rollouts of the same question must already differ in
answer belief or in their subsequent belief updates. Correct trajectories
should then exhibit recovery or sustained improvement that cannot be reduced
to the late answer-likelihood level alone.
```

If the early level is nearly constant within each question, then
`gain = late_level - early_level` is approximately a shifted late level. In that case, gain is not an independent process signal even when its raw AUC is high.

### H4: Format-agnostic generalization

The same score should distinguish correct and incorrect frozen-policy rollouts on free-form numerical/symbolic math.

### H5: RL utility

Adding group-normalized answer-likelihood progress to answer correctness should improve held-out free-form accuracy over answer-only GRPO under matched compute and decoding.

### Evidence hierarchy

```text
Stage A: measurement validity and incremental process information
Stage B: format-agnostic frozen-policy generalization
Stage C: causal reward utility under matched RL training
```

Stage A/B cannot establish that the signal is a useful reward. Offline discrimination is necessary for entry into Stage C, but Stage C remains the main scientific gamble because reward optimization can Goodhart even a strong frozen-policy diagnostic.

## 3. Notation And Score Definition

For question `q` and rollout `i`:

```text
x_q       = problem text, image if present, and system/user prompt
z_qi,<=j  = reasoning prefix ending at probe j
c         = fixed answer interface
Y*_q      = accepted surface forms of the correct semantic answer
y^(m)     = one accepted surface form in Y*_q
```

### 3.1 Teacher-forced answer score

The model does not generate the target during probing. It receives the prefix, fixed answer cue, and teacher-forced target sequence. Only target-answer tokens and a fixed answer terminator are scored.

For surface form `y^(m)`:

```text
s_j^(m) = mean token logprob of [y^(m), ANSWER_END]
          conditioned on [x_q, z_qi,<=j, c]
```

Formally:

```text
s_j^(m) = 1 / (T_m + 1) * (
    sum_t log P(y_t^(m) | x_q, z_qi,<=j, c, y_<t^(m))
    + log P(ANSWER_END | x_q, z_qi,<=j, c, y^(m))
)
```

`ANSWER_END` prevents a prefix answer such as `1` from receiving the same interpretation as the first token of `10`.

### 3.2 Surface-form aggregation

Do not select the highest-scoring surface form independently at every prefix; switching the winning format can create artificial gain.

Compute gain per surface form first:

```text
g_a_b^(m) = s_b^(m) - s_a^(m)
```

Then aggregate:

```text
gold_gain_a_b = median_m g_a_b^(m)
```

For level-only diagnostics, define:

```text
gold_level_j = median_m s_j^(m)
```

The canonical-only and mean-over-surface-forms versions remain required sensitivity checks. The median level is not interpreted as an exact equivalence-class probability; it is a robust format-aggregated score.

Primary aggregation:

```text
median over accepted surface forms
```

Required sensitivity checks:

```text
canonical-only gain
mean-over-surface-forms gain
minimum surface-form gain
surface-form gain standard deviation
```

### 3.3 Level features

```text
gold_level_90
gold_level_trimmed
gold_relative_level_90 = gold_level_90 - gold_level_0
```

Level features are verifier diagnostics. They cannot independently pass the process-signal gate.

### 3.4 Process features

Primary:

```text
gold_gain_25_90 = median_m [s_90^(m) - s_25^(m)]
```

Secondary:

```text
gold_gain_25_trimmed = median_m [s_trimmed^(m) - s_25^(m)]
gold_trajectory_slope
gold_positive_gain_rate
gold_monotonicity_violation_rate
```

Retain every adjacent probe difference rather than only its scalar summaries. For adjacent probe positions `j-1` and `j`, compute the difference separately for each accepted surface form and aggregate afterward:

```text
delta_j^(m) = s_j^(m) - s_(j-1)^(m)
gold_step_gain_j = median_m delta_j^(m)
```

When probe intervals are unequal, also normalize by the amount of thinking progress:

```text
gold_step_gain_rate_j = gold_step_gain_j / (frac_j - frac_(j-1))
```

The ordered vectors are retained as mechanism diagnostics:

```text
gold_step_gain_vector = [gold_step_gain_1, ..., gold_step_gain_J]
gold_step_gain_rate_vector = [gold_step_gain_rate_1, ..., gold_step_gain_rate_J]
```

The adjacent sequence is `prompt 0% -> numeric thinking probes -> thinking 100%`. `trimmed-final` is an alternative edited prefix, not a later time point, so it is excluded from the adjacent vector and compared separately through `gold_gain_25_trimmed` and its matched level control.

Do not substitute `median_m s_90^(m) - median_m s_25^(m)` for the primary endpoint gain. Median-of-per-surface gains and gain-of-median levels are generally unequal. `gold_level_j = median_m s_j^(m)` remains valid only for level diagnostics and level-control rewards.

If un-clipped adjacent gains are averaged, they telescope to endpoint gain. Therefore the scalar adjacent mean is not reported as an independent feature. The full step-gain vector remains informative because it preserves when belief moved, whether it reversed, and whether correct and incorrect trajectories diverged before the final answer.

### 3.5 Content-contrastive score

For MCQ or free-form questions with frozen hard negatives:

```text
content_margin_j = score_j(gold content)
                   - max_k score_j(wrong content k)

content_margin_gain_25_90 = content_margin_90 - content_margin_25
```

This is an ablation that determines whether explicit alternatives are necessary for a strong signal.

### 4.5 Letter scoring under neutral interfaces

The `I0` anchor must reproduce the legacy measurement exactly:

```text
read the next-token A/B/C/D logits immediately after the original cue
compute correct-letter logit minus max wrong-letter logit
do not add answer content or a terminator to this legacy anchor
```

Under `I1` and `I2`, compute both letter measurements:

```text
neutral_letter_first_token_margin:
  read the first answer-token A/B/C/D logits after the neutral cue

neutral_letter_sequence_margin:
  teacher-force each complete letter target plus ANSWER_END
  use the same normalized sequence scorer as answer content
```

The first-token version implements the clean same-interface control against content scoring. The sequence version checks whether any difference is caused by first-token versus full-sequence scoring. Do not assume each label is one token when constructing the sequence version.

For the first-token cell, each A/B/C/D target must occupy exactly one context-tokenized
token under the rendered Qwen chat template. A violation is a pipeline error. The sequence
cell remains valid for multi-token targets.

```text
neutral_letter_sequence_margin_j = score_j(correct letter sequence)
                                   - max score_j(wrong letter sequences)
```

This cell isolates the interface effect from the content-representation effect.

### 4.10 Stage A decision gates

Apply gates in this order to avoid overlapping labels:

```text
1. PIPELINE-FAIL
2. INTERFACE-FAIL or REPRESENTATION-FAIL
3. LEVEL-EQUIVALENT
4. PASS-PROCESS
5. CONTRASTIVE-ONLY
6. BORDERLINE-PROCESS
7. VERIFIER-ONLY
8. no-signal failure if none of the above applies
```

#### PASS-PROCESS

At least one gold-only process feature must satisfy all primary conditions:

```text
within-question AUC >= 0.70
question-bootstrap CI lower bound > 0.60
positive-correlation fraction >= 0.65
I1 versus I2 AUC difference <= 0.03
pre-explicit-answer or trimmed AUC >= 0.65
label-permutation AUC change <= 0.02
mean paired delta AUC = AUC(gain) - AUC(matched late level) > 0
question-bootstrap 95% CI lower bound for paired delta AUC > 0
cross-fitted level+gain model improves over level-only in the predeclared metric
```

Decision:

```text
Proceed to Stage B free-form frozen-policy discovery.
```

#### LEVEL-EQUIVALENT

```text
gain/slope AUC >= 0.70
but paired gain-minus-level AUC CI includes 0
or the cross-fitted level+gain model does not improve over level-only
```

Interpretation:

```text
The apparent process feature is empirically reducible to late/final confidence.
The result supports a verifier signal, not trajectory-specific process evidence.
```

Decision:

```text
Stop the proposed process-reward branch before Stage B/C.
Redesign a non-telescoping trajectory feature with an explicit mechanism,
then repeat Stage A without reusing the held-out confirmatory questions.
```

#### BORDERLINE-PROCESS

```text
gain/slope AUC in [0.65, 0.70)
or CI lower bound in (0.50, 0.60]
```

Decision:

```text
Proceed only to a small free-form frozen-policy discovery.
Do not implement or launch RL reward training yet.
```

#### VERIFIER-ONLY

```text
gold level AUC >= 0.75
but all gold gain/slope AUC values < 0.65
or their confidence intervals include 0.50
```

Interpretation:

```text
The method is a confidence/verifier signal, not a validated process signal.
```

Decision:

```text
Stop the process-reward branch.
Do not describe this outcome as backward-compatibility success for RL.
```

#### INTERFACE-FAIL

```text
I0 letter reproduces the original result
but I1/I2 letter gain collapses below 0.65
```

Decision:

```text
The interface is the dominant measurement variable.
Redesign or ensemble the answer interface before evaluating content targets.
```

#### REPRESENTATION-FAIL

```text
neutral-interface letter gain >= 0.70
but gold-content gain < 0.60
```

Decision:

```text
Inspect target normalization, answer length, surface forms, and content already present in the prompt.
Do not enter free-form RL.
```

#### CONTRASTIVE-ONLY

```text
content-contrastive gain >= 0.70
but gold-only gain < 0.65
```

Interpretation:

```text
Negative candidates provide a necessary answer-space coordinate system.
```

Decision:

```text
Free-form experiments must include frozen hard negatives.
The paper cannot claim a candidate-free primary method.
```

#### PIPELINE-FAIL

```text
I0 letter does not reproduce the existing signal
or scoring/boundary failures exceed 1%
```

Decision:

```text
Stop and debug. No scientific interpretation is permitted.
```

## 5. Answer Normalization And Surface Forms

### 5.1 Separate semantic answers from strings

Each answer has:

```text
semantic object:
  the mathematical value or expression used by the verifier

surface forms:
  finite strings used for teacher-forced likelihood scoring
```

Example:

```text
semantic object: Rational(1, 2)

accepted surface forms:
  1/2
  \frac{1}{2}
  0.5
```

`50%` is included only when the task evaluator accepts a percentage for that question.

### 5.2 Supported first-version answer types

```text
integers
rational numbers
finite decimals
percentages with explicit compatibility
simple radicals
simple symbolic expressions
small ordered tuples
small unordered finite sets
```

### 5.3 Excluded first-version answer types

```text
proofs
long natural-language explanations
answers requiring an unrestricted semantic judge
ambiguous units
complex matrices or large structured objects
expressions that the verifier cannot parse reliably
```

The initial claim is limited to:

```text
symbolically verifiable free-form answers
```

### 5.4 Dataset-specific normalization

#### GSM8K

```text
extract the value after the final answer marker
remove thousands separators
normalize sign and decimal notation
convert finite decimals and fractions to exact rationals
track units separately
```

#### MATH

```text
extract the final boxed expression
parse with math-verify/SymPy-compatible tooling
simplify numeric and symbolic expressions
sort finite sets where order is irrelevant
preserve tuple order where order is meaningful
exclude records that do not round-trip through the verifier
```

### 5.5 Independent outcome evaluation

Training/evaluation correctness is not exact string equality:

```text
R_answer = symbolic_equivalent(predicted_answer, semantic_gold)
```

Process scoring uses the accepted surface forms:

```text
R_progress = function of teacher-forced likelihood trajectory over Y*
```

These two components must use separate code paths and tests.

## 7. Stage C: Free-Form GRPO Pilot

### 7.1 Reward variants

#### A2: Answer-only baseline

```text
R_total = R_answer
```

#### L1-ref: Frozen-reference final/late answer-likelihood level control

```text
B_level_ref = clip(zscore_group(gold_relative_level_90_ref), -2, 2)
R_total = R_answer + lambda * B_level_ref
```

This is a verifier/confidence control, not the proposed process method.

#### P1-ref: Frozen-reference answer-likelihood progress

```text
G_raw_ref = gold_gain_25_90_ref
B_progress_ref = clip(zscore_group(G_raw_ref), -2, 2)
R_total = R_answer + lambda * B_progress_ref
```

This is the primary process-reward setting because its scorer remains fixed during training.

#### P1-self: Rollout-time actor answer-likelihood progress

```text
G_raw_self = gold_gain_25_90_self
B_progress_self = clip(zscore_group(G_raw_self), -2, 2)
R_total = R_answer + lambda * B_progress_self
```

This is a co-primary stationarity comparison. Scores are computed by the rollout-time old actor and detached before the policy update.

#### P2: Contrastive progress, conditional branch

Run only if Stage A or B shows that hard negatives are necessary:

```text
M_raw = content_margin_gain_25_90
B_contrast = clip(zscore_group(M_raw), -2, 2)
R_total = R_answer + lambda * B_contrast
```

### 7.2 Scorer policy

Primary scorer:

```text
frozen initial/reference model
fixed checkpoint and fixed scoring interface for the full run
scores detached from gradient computation
```

Co-primary non-stationary comparison:

```text
rollout-time actor/old policy before each policy update
scores detached from gradient computation
```

The frozen scorer prevents a self-reward loop in which the actor can increase measured gain by reshaping its own early and late distributions without improving reasoning. `P1-ref` and `P1-self` must both be run under matched data, decoding, seeds, and update counts. If only `P1-self` succeeds, the result is reported as self-referential shaping and does not establish a stationary process reward.

An `L1-self` level control is added only if `P1-self` is scientifically interpreted; it is not needed to establish the primary `P1-ref` versus `L1-ref` comparison.

### 7.3 Pilot configuration

```text
model: Qwen3-8B, thinking enabled
dataset: supported MATH training problems
train questions: 200
held-out validation: at least 256
rollout.n: 8 if resource smoke passes; otherwise 4 with matched baseline
max_response_length: selected by Stage B length audit
training steps: 50
seeds: 42, 43, 44
LoRA rank: 8
initial lambda: 0.1
```

Do not run a full lambda grid initially. Use frozen-policy reward/ranking sensitivity to decide whether `0.05` or `0.2` is needed after the primary pilot.

### 7.4 Matched-comparison requirements

All reward variants must use the same:

```text
base checkpoint
train and validation splits
rollout count
decoding parameters
maximum lengths
training steps
LoRA configuration
seed set
evaluation code
```

Compute overhead from answer scoring must be reported separately. A compute-matched control should reduce A2 throughput or add neutral forwards if reviewers could attribute the result to extra computation.

### 7.5 Main evaluation

```text
symbolic answer accuracy
balanced accuracy by answer type and difficulty
paired wins/losses versus A2
question-clustered confidence interval
response length and truncation
invalid/unsupported answer rate
format distribution
pass@k when available
```

### 7.6 Process diagnostics

```text
fraction of groups with nonzero B_progress variance
fraction of groups where B_progress changes ranking
mixed/all-wrong/all-correct group proportions
corr(R_answer, B_progress) on mixed groups only
all-wrong group ranking behavior
answer-likelihood trajectory before and after training
early explicit-answer rate
surface-form gain disagreement
frozen-reference versus self-score rank agreement over training
early-level and late-level drift under both scorers
fraction of self-score gain attributable to lower early score rather than higher late score
```

Do not average answer/gain correlation over constant-answer groups and interpret the resulting near-zero value as lack of signal. Correlation is defined only for mixed groups.

### 7.7 Stage C success gate

The stationary process method is considered supported only if:

```text
pooled P1-ref - A2 accuracy delta > 0
question-clustered 95% CI lower bound > 0
at least two of three seed deltas are positive
paired wins exceed losses in the pooled audit
invalid answer rate does not materially increase
truncation and response length do not explain the gain
no answer-format or answer-type collapse occurs
P1-ref outperforms or adds value beyond L1-ref
```

`P1-self` is interpreted separately:

```text
P1-ref and P1-self pass:
  process reward is useful and robust to scorer stationarity choice

P1-ref passes, P1-self fails:
  stationary process reward is supported; self-scoring is unstable

P1-self passes, P1-ref fails:
  self-referential shaping result only; no stationary process-reward claim

neither passes:
  offline discrimination did not translate into reward utility
```

If `P1-ref` does not outperform `L1-ref`, the evidence supports confidence shaping rather than trajectory-specific process supervision.

### 7.8 Stop conditions

Stop the pilot before scaling if any occurs:

```text
reward/probe failure rate > 1%
answer normalization failure > 1% on supported records
invalid answer rate increases by more than 2 percentage points
response length drops by > 50% across two checkpoints
truncation increases by > 10 percentage points
surface-form gain disagreement becomes dominant
reward becomes strongly correlated with length after controls
one answer type or format dominates predictions
```

## 9. Paper Claims Allowed By Each Outcome

### Outcome A: Gold gain passes MCQ, free-form, and RL

Allowed claim:

```text
Answer-likelihood progress is a format-agnostic process signal
that improves outcome-based GRPO on verifiable free-form reasoning.
```

### Outcome B: Level passes, gain fails

Allowed claim:

```text
Answer likelihood is a useful intermediate/final verifier signal.
```

Not allowed:

```text
The trajectory provides effective process supervision.
```

This outcome also includes a high-AUC gain whose paired incremental AUC over matched late level is not positive with a confidence interval above zero (`LEVEL-EQUIVALENT`).

### Outcome C: Contrastive passes, gold-only fails

Allowed claim:

```text
Candidate-conditioned belief progress is useful,
but negative candidates are necessary to define the answer space.
```

### Outcome D: Offline process signal passes, RL fails

Allowed claim:

```text
Correctness discrimination does not automatically imply reward utility.
```

The analysis should then focus on all-wrong groups, recoverability, reward stationarity, and causal versus correlational signal.

### Outcome E: Interface dominates

Allowed claim:

```text
Forced-answer confidence measurements are highly interface-dependent.
```

This is a measurement result, not a robust process-reward method.
